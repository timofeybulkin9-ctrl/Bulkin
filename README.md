# ShiftPlanner

Приложение для автоматического планирования смен операторов контакт-центра под почасовую нагрузку.
Учебный проект. **Все демонстрационные данные синтетические**, компания обобщённая (вымышленная).

## Бизнес-проблема

Руководитель смены составляет график вручную в Excel, без привязки к почасовому профилю нагрузки.
В пиковые часы операторов не хватает (очереди, потерянные звонки), в спокойные их избыток (оплата простоя).
Масштаб проблемы в реальной компании нужно проверять на её данных; приложение измеряет его на загруженной истории.

## Что делает приложение

1. Загружает CSV с историей звонков (или генерирует синтетические демо-данные) и проверяет формат.
2. Строит профиль «день недели × час» и считает, сколько операторов нужно (формула Erlang C или упрощённо).
3. Строит недельный график смен: точный метод (PuLP), при неудаче жадный алгоритм.
4. Показывает потребность и план, тепловую карту дефицита и избытка.
5. Сравнивает результат с базовым («плоским») графиком: те же типовые смены, поровну каждый день, то же общее число смен.
6. Считает KPI, назначает сотрудников по именам (отдых между сменами не меньше 11 часов, не больше 5 дней в неделю), выгружает Excel/CSV.
7. Позволяет вручную поправить график с проверкой ограничений.

## KPI

Доля часов дефицита и избытка, покрытие нагрузки, операторо-часы дефицита и избытка, условная стоимость простоя
(ставка задаётся пользователем), целевая функция (штраф).

## Технологии

Python 3.10+, Streamlit (интерфейс), pandas и numpy (данные), Plotly (графики), PuLP с решателем CBC (оптимизация),
openpyxl (Excel), pytest (тесты). Всё бесплатное, платных API нет.

## Запуск

```bash
# 1. Создать виртуальное окружение
python -m venv .venv
# Windows:      .venv\Scripts\activate
# macOS/Linux:  source .venv/bin/activate

# 2. Установить библиотеки
pip install -r requirements.txt

# 3. Запустить приложение
streamlit run app.py
```

Приложение откроется в браузере. Нажмите «Сгенерировать демо-данные», затем на вкладке «График» «Построить график».

## Формат CSV

| Колонка | Смысл | Пример |
|---|---|---|
| timestamp | дата и час | 2025-03-03 10:00 |
| calls | число обращений за час | 42 |
| aht_sec | средняя длительность обработки, сек | 280 |

Лишние колонки игнорируются. Пример файла: `data/demo_calls.csv` (синтетика). Пересоздать: `python -m core.data_gen`.

## Тесты

```bash
pytest
```

Тесты с PuLP пропускаются, если библиотека не установлена.

## Структура

```
app.py             интерфейс Streamlit (без расчётов)

core/data_gen.py   генератор синтетических данных

core/optimizer.py  PuLP и жадный алгоритм, проверка ограничений
core/baseline.py   базовый («плоский») график
core/kpi.py        покрытие и KPI
core/roster.py     назначение сотрудников
core/export.py     выгрузка в CSV/Excel
tests/             тесты бизнес-логики
data/              демо-данные (синтетика)
```

## Как работает оптимизация (простыми словами)

Для каждого дня и каждой смены выбирается целое число операторов. В каждом часе сравниваем «сколько вышло» и «сколько нужно»:
нехватка это дефицит, лишние люди это избыток. Минимизируем взвешенную сумму (дефицит штрафуется строже, по умолчанию 3 к 1).
Ограничения: в день не больше смен, чем операторов; за неделю не больше `операторов × 5` смен.

## Допущения и ограничения

- Нагрузка предсказуема по среднему профилю «день недели × час», без прогнозирования ML.
- Одна очередь, один тип навыка, смены по 8 часов без перерывов.
- Не учитываются отпуска, больничные, обучения, обеденные перерывы.
- Реальный эффект нужно проверять на данных конкретной компании.
